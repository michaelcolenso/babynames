# SEO Fixes — Implementation Notes

**Date:** 2026-05-29
**Implements:** the code-actionable findings from `2026-05-29-seo-audit.md` and `2026-05-29-seo-audit-followup.md`.

## What shipped

### 1. Homepage cache-variant collision (P1) — `functions/_middleware.ts`
The edge cache keyed `/` by URL only, so the HTML and `Accept: text/markdown` representations collided and whichever populated a PoP's cache first was served to everyone (the homepage intermittently returning raw Markdown). The Cloudflare Cache API keys on URL, **not** on the `X-Cache-Key` request header the old code relied on — so that mechanism was inert. Fix: fold the negotiated variant into a synthetic, internal-only cache-key URL (`__nv_variant=html|md`) used for both lookup and store, so the two representations cache separately. The param never reaches clients.

### 2. Server-rendered internal links on the hub pages (P2) — `functions/[slug].ts`, `packages/shared/src/render-landing.ts`
`/extinct`, `/endangered`, `/rising`, `/comeback`, and `/year` were static shells whose tables were built client-side (`renderLandingTable`), so the initial HTML contained **no** `/name/` or `/year/` links. Now the Function injects a server-rendered table (top 100 names per hub) / a full birth-year index (1880–present) into the shell before serving it. New shared module `render-landing.ts` (`renderLandingTableHTML`, `renderYearIndexHTML`) mirrors the client markup so the SSR and client renders match. The client still hydrates the full table on top (unchanged behavior); injection is best-effort and falls back to the static shell on any D1 error.

### 3. OG image type mismatch (P2) — 11 static HTML files
All declared `og:image:type = image/svg+xml` while pointing at `/api/og/default`, which returns `image/png`. Corrected to `image/png` across `index.html`, the hub pages, `about.html`, `blog/index.html`, and the viz pages.

### 4. Sitemap `<lastmod>` (P2) — `functions/sitemap.xml.ts`
Added a stable, dataset-wide `<lastmod>` (May 1 of `maxYear + 1`, clamped to today) reflecting the once-a-year SSA ingest, so crawlers can cheaply tell the corpus is unchanged between annual updates.

### 5. Security headers (P3) — `functions/_middleware.ts` + `public/_headers`
Pages `_headers` does not apply to Function responses, so HSTS / `X-Content-Type-Options` / `Referrer-Policy` were inconsistent. Added them to every Function response via the middleware, and a `/*` block in `_headers` for static assets. Existing header values are preserved.

## Verify after deploy

```bash
# 1. Homepage is HTML on consecutive requests; agents still get Markdown.
for i in 1 2 3; do curl -s -o /dev/null -w '%{content_type}\n' https://nobodynamed.com/; done   # text/html ×3
curl -s -H 'Accept: text/markdown' https://nobodynamed.com/ | head -1                            # # NobodyNamed

# 2. Hubs ship crawlable links in raw HTML.
for p in /extinct /endangered /rising /comeback; do echo -n "$p "; curl -s "https://nobodynamed.com$p" | grep -oE 'href="/name/[^"]+"' | sort -u | wc -l; done   # > 0
curl -s https://nobodynamed.com/year | grep -oE 'href="/year/[0-9]{4}/"' | sort -u | wc -l        # ~146

# 3. OG type, sitemap lastmod, security headers.
curl -s https://nobodynamed.com/ | grep 'og:image:type'                                          # image/png
curl -s https://nobodynamed.com/sitemap.xml | grep -m1 lastmod
curl -sI https://nobodynamed.com/name/Emma/ | grep -iE 'strict-transport|x-content-type|referrer-policy'
```

- **Thin-page gating / coverage expansion / state-level & living-bearer features** — product decisions with quality trade-offs; deferred to a dedicated change.
- **Timely 2025-release editorial content** — content authoring, out of scope for these technical fixes.
